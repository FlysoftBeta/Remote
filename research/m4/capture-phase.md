## Harness
`summary.latDecoded` and `summary.i2decoded` use the detected frame's rVFC `presentationTime`. `summary.i2display` adds an explicit same-frame `expectedDisplayTime` input glass estimate. The existing `lat`, `rx`, and `i2p` values are unchanged: real-endpoint `i2p` is callback-time colour detection, while marker-sequence `i2p` already uses display time. CSV retains the original four columns and appends decoded capture/input and input glass columns. Missing `presentationTime` produces no decoded sample.

The capture metric retains the old `lat` starting point: the sender's embedded page-draw marker timestamp mapped through RKClock, not endpoint `capture_end`. Only the end timestamp changes to presentationTime. Input measurements retain their existing send timestamp and detect the same marker sequence/colour-flip frame for both end timestamps.

## S5 design fallback: one admitted external BeginFrame per root

This is a design, not an implemented or validated fix. The minimal flags can reach the desired same-BeginFrame case in one run, yet repeat runs retain a whole-frame backlog. [I] Control of frame admission and completion is the next defensible experiment; increasing pool depth or changing copy-result delivery does not make an already-stale aggregated surface fresh.

1. **Opt-in root control.** Under `ui::IsPrtsRemoteMode()` and a new `--prts-external-begin-frame` switch, change `DesktopWindowTreeHostWin::Init` at `ui/views/widget/desktop_aura/desktop_window_tree_host_win.cc:327` to call `CreateCompositor(force_sw, true)` and set `compositor()->set_wait_for_all_frame_sinks(false)` before initialization. [V] `ui/aura/window_tree_host.cc:543-556` already forwards this immutable option; `ui/compositor/compositor.h:373-375` exposes the Windows callback API. [V] `root_compositor_frame_sink_impl.cc:170-181` selects the Mojo external source ahead of Windows vsync when the controller is supplied. Keep patch 17 for presentation feedback; the endpoint admission clock should drive only the controlled root's BeginFrames. No GPU copy or delivery hooks are needed for this enabling change.

2. **Browser bridge, endpoint clock.** Add `PrtsFramePacer` in `chrome/browser/prts/`, owned per browser root/generation by the registry/controller. Extend the browser Mojo interface with proposed `PaceConfig(window, generation, enabled, interval)` and `PaceTick(window, generation, tick_seq, frame_time, deadline) => (tick_seq, BeginFrameAck)` messages. [V] Current `chrome/browser/prts/mojom/prts.mojom` has neither method; the design/02 contract is still only a plan. Negotiate a protocol version/capability before sending them. Construct BeginFrameArgs in the browser with a valid source ID, strictly increasing sequence/frame_time, positive interval, and a deadline initially `frame_time + 0.8 * interval` as in design/02. Use the endpoint's existing monotonic clock and absolute 60 Hz grid; transport is local Mojo, so no network wall-clock mapping is involved. [I] Keep any source-id/sequence allocation consistent with `viz::BeginFrameArgs` and compositor recreation rather than reusing sequence 0.

3. **Bound admission, never catch up.** At most one `IssueExternalBeginFrame` RPC may be outstanding per root. [V] `external_begin_frame_source_mojo.cc:37-44` rejects overlaps as a bad message; `ui/compositor/compositor.cc:766-778` also buffers only one pending call before controller binding. On a late completion, skip expired absolute deadlines and admit the newest eligible tick; do not enqueue the missed ticks or immediately run a burst. Consume accumulated input before admitting that tick. Keep refresh requests for startup/idle/keyframe recovery, not as an independent 60 Hz capture timer. On window destruction, suspend, or Viz restart, invalidate old callbacks using the root generation, drop pending ticks, recreate the controller, and bootstrap once after the capture target is ready.

4. **Keep the completion domains distinct.** [V] `ExternalBeginFrameSourceMojo::OnDisplayDidFinishFrame` (`:156-176`) returns a drawn/undrawn ACK; it does not signal a completed copy, a shared-GPU fence, an exported buffer or encode completion. `wait_for_all_frame_sinks=false` avoids waiting indefinitely for joining sinks and must not be treated as proof that every child submitted fresh content. Gate further admission on the RPC ACK plus a bounded capture/encoder credit policy, and trace renderer/child readiness to verify the captured content belongs to the admitted frame. Use `CompositorFrameMetadata.begin_frame_ack` (`components/viz/common/quads/compositor_frame_metadata.h:169`) and frame token (`:178`) in request-side trace records; join them to existing capture_begin/capture_end and page frame IDs. Do not infer identity from the time at which an asynchronous copy result arrives. Leave the delivery path and the other task's GPU-fence ownership unchanged.

5. **Renderer policy is part of the experiment.** Test external admission with and without full-pipeline scheduling, then with and without NoCompositorFrameAcks; do not promote either flag from the isolated lucky run. In full-pipeline mode, old active/pending trees can still survive across callbacks, and the stock switch makes surface activation deadlines unlimited (`components/viz/common/switches.cc:69-73`). Bootstrap by draining or recreating the controlled compositor/capturer state before starting timed measurement. If an unresponsive child blocks progress, expire the pacing transaction through a deliberate recovery/recreation path rather than issuing an overlapping tick or fabricating a success ACK. [I] The bounded watchdog duration and which embedded sinks participate require an explicit product decision; a draw deadline alone does not provide that recovery.

6. **Acceptance for that future implementation.** Repeat five independent 60 s marker launches, tracing admitted tick -> renderer rAF/commit/activation -> root aggregate -> capture_begin for the actual pixel frame. Each run must stay in the same-BeginFrame phase cluster (the M3 ~1.6 ms case, allowing measured processing cost, with no sustained +16.7/+33.3 ms cluster), preserve the 60 fps target, and survive idle refresh, resize, new/closed child roots, navigation, slow iframe/long JS, and a Viz restart. Then run two 60 s S/d25j5-c12 trials and report P50/P80/P95/P99 for both decoded metrics and both glass estimates. The target remains decoded P80 <100 ms/P99 <200 ms; passing a display estimate or an ACK timing is insufficient.
